# Vicu 1.5.0 release + macOS signing & notarization — Design

**Date:** 2026-06-12
**Status:** Approved (pending spec review)

## Overview

Cut the first stable **1.5.0** release, consolidating the five 1.5.0 betas into a
single release message, and — now that an Apple Developer license is available —
**sign and notarize the macOS build** so the unsigned-app workaround is no longer
needed.

Two coordinated workstreams:

- **Part A — macOS signing + notarization:** wire the release pipeline to produce
  a Developer ID–signed, Apple-notarized DMG.
- **Part B — version bump + consolidated release:** bump to `1.5.0`, write unified
  release notes, tag, and let CI publish a stable release.

**Decisions locked in:**

| Decision | Choice |
|---|---|
| Sequencing | Sign first, **verify**, then tag `v1.5.0` so it ships signed from day one |
| Notarization credential | App-specific password (`APPLE_ID` + `APPLE_APP_SPECIFIC_PASSWORD` + `APPLE_TEAM_ID`) |
| Mac architecture | arm64-only (Apple Silicon), unchanged |
| Missing-secret behavior | Conditional fallback — degrade to unsigned, never hard-fail the release |

## Part A — macOS code signing + notarization

### Already in place (no work needed)

- `electron-builder.yml` `mac:` block: `hardenedRuntime: true`, `gatekeeperAssess: false`,
  `entitlements` / `entitlementsInherit` → `build/entitlements.mac.plist`.
- `build/entitlements.mac.plist`: `allow-jit`, `allow-unsigned-executable-memory`,
  `disable-library-validation`, `network.client`/`server`, `automation.apple-events` —
  the correct hardened-runtime entitlement set for a notarized Electron app.
- `.github/workflows/build-macos.yml`: already imports a `.p12` from
  `BUILD_CERTIFICATE_BASE64` into a temporary keychain when the secret is present,
  and toggles `CSC_IDENTITY_AUTO_DISCOVERY` accordingly.

electron-builder 25 bundles `@electron/notarize` and uses `notarytool`. **No new npm
dependency is required.**

### Config / code changes

**1. `electron-builder.yml` — enable notarization**

Add to the `mac:` block:

```yaml
mac:
  # ...existing keys unchanged (icon, category, hardenedRuntime, entitlements, target: arm64 dmg)...
  notarize: true
```

- `notarize: true` makes electron-builder run `notarytool` and staple the `.app`.
  The team ID is read from the `APPLE_TEAM_ID` env var.
- `dmg.sign: false` **stays** — only the `.app` needs signing+notarization; the DMG is
  just a carrier for the already-stapled app.
- Mac `target` stays `dmg` / `arch: [arm64]`.

**2. `.github/workflows/release.yml` — sign + notarize in the `build-macos` job**

Currently the job hardcodes `CSC_IDENTITY_AUTO_DISCOVERY: false` and never imports a
cert. Change it to mirror `build-macos.yml`:

- Add an **"Import signing certificate"** step, gated on
  `if: env.BUILD_CERTIFICATE_BASE64 != ''`, that decodes `BUILD_CERTIFICATE_BASE64`
  into a temporary keychain (same `security create-keychain` / `import` /
  `set-key-partition-list` sequence as `build-macos.yml`).
- In the "Build and publish" step, set:
  - `CSC_IDENTITY_AUTO_DISCOVERY: ${{ secrets.BUILD_CERTIFICATE_BASE64 != '' && 'true' || 'false' }}`
    (conditional fallback — unsigned, not failed, if the secret is missing).
  - `APPLE_ID: ${{ secrets.APPLE_ID }}`
  - `APPLE_APP_SPECIFIC_PASSWORD: ${{ secrets.APPLE_APP_SPECIFIC_PASSWORD }}`
  - `APPLE_TEAM_ID: ${{ secrets.APPLE_TEAM_ID }}`
- Add a **"Cleanup keychain"** step (`if: always()`), same as `build-macos.yml`.
- Keep the existing "Remove blockmap assets" step.

**3. `.github/workflows/build-macos.yml` — make the test build notarize too**

It already imports the cert. Add the three `APPLE_*` env vars to its "Package macOS"
step so a manual run produces a fully **signed + notarized** DMG — this is the
pre-tag verification path.

**4. `README.md` — drop the workaround**

Remove the "macOS — first launch (unsigned app)" section (the **Open Anyway** /
`xattr -cr /Applications/Vicu.app` instructions, lines ~99–111) and replace with
normal install copy: open the DMG, drag **Vicu** to **Applications**, launch. (A
one-time "downloaded from the internet — are you sure you want to open it?" prompt is
normal and is *not* the Gatekeeper block.)

### Manual steps (user — cannot be automated)

> Do these on the Mac with the Apple Developer account signed in.

**A. Create the Developer ID Application certificate**
1. Xcode → **Settings → Accounts**, select the team, **Manage Certificates → + → Developer ID Application**.
   (Or developer.apple.com → Certificates → **+** → *Developer ID Application*, upload a CSR from Keychain Access → *Certificate Assistant → Request a Certificate from a Certificate Authority*.)
2. In **Keychain Access**, find the new "Developer ID Application: <name> (TEAMID)" cert,
   right-click → **Export** → save as `cert.p12`, set a password (this is `P12_PASSWORD`).
3. Base64-encode it: `base64 -i cert.p12 | pbcopy` → this is `BUILD_CERTIFICATE_BASE64`.

**B. Create an app-specific password**
1. appleid.apple.com → **Sign-In and Security → App-Specific Passwords → +**.
2. Name it e.g. "Vicu notarization" → copy the `xxxx-xxxx-xxxx-xxxx` value → this is
   `APPLE_APP_SPECIFIC_PASSWORD`.

**C. Find the Team ID**
- developer.apple.com → **Membership** → 10-character **Team ID** → this is `APPLE_TEAM_ID`.

**D. Add GitHub repo secrets** (Settings → Secrets and variables → Actions → New repository secret):

| Secret | Value |
|---|---|
| `BUILD_CERTIFICATE_BASE64` | base64 of the `.p12` |
| `P12_PASSWORD` | the `.p12` export password |
| `KEYCHAIN_PASSWORD` | any random string (temp keychain password) |
| `APPLE_ID` | Apple ID email |
| `APPLE_APP_SPECIFIC_PASSWORD` | the app-specific password from step B |
| `APPLE_TEAM_ID` | the 10-char team ID from step C |

### Verification (before tagging)

1. Trigger `build-macos.yml` manually (Actions → **Build macOS** → **Run workflow**).
2. Download the `vicu-macos-arm64-dmg` artifact.
3. Mount the DMG and confirm, on the Mac:
   - `spctl -a -t open --context context:primary-signature -vvv /Volumes/Vicu*/Vicu.app` → `accepted`, `source=Notarized Developer ID`.
   - `stapler validate /Volumes/Vicu*/Vicu.app` → "The validate action worked!".
   - Or simply: it opens with a normal "are you sure" prompt and **no** "cannot be
     opened because the developer cannot be verified" block.
4. Only once this passes do we proceed to tag the release.

## Part B — Version bump + consolidated 1.5.0 release

1. **`package.json`**: `"version": "1.5.0-beta.5"` → `"1.5.0"`.
2. **Consolidated release notes** (`v1.5.0` GitHub release body) folding in all five
   betas. Draft below — finalized at release time.
3. **Commit** version bump + Part A config/README changes on a branch, merge to `main`.
4. **Tag `v1.5.0`** and push. The tag has no `-`, so `create-release` in `release.yml`
   marks it a **stable** (non-prerelease) release. CI builds Windows (NSIS x64),
   macOS (signed+notarized arm64 DMG), and Linux (AppImage x64 + arm64), all publishing
   to the same draft release, which electron-builder then publishes.
5. After CI completes, set the consolidated notes via `gh release edit v1.5.0 --notes-file …`.

## Sequencing

1. Implement all Part A config/code changes + Part B version bump on a branch; commit.
2. **User** completes the manual cert + secrets setup (Part A manual steps).
3. **User** runs `build-macos.yml` manually → confirm signed + notarized (Verification).
4. Merge to `main`, tag `v1.5.0`, push → stable release ships, Mac signed.
5. After CI: finalize release notes via `gh release edit`.

## Risks & notes

- **Release won't break on a missing secret:** conditional `CSC_IDENTITY_AUTO_DISCOVERY`
  degrades to unsigned rather than failing CI. Verification step 3 catches misconfig
  before the tag anyway.
- **Cert type matters:** must be **Developer ID Application** — not "Apple Development"
  or "Mac App Distribution" — or Gatekeeper still blocks direct downloads.
- Notarization adds ~2–5 min to the Mac build.
- A newly notarized app still shows a one-time "downloaded from the internet" prompt on
  first open. That is expected and is *not* the Gatekeeper block; no workaround needed.

## Out of scope

- Intel (x64) / universal Mac builds — staying arm64-only.
- App Store Connect API key auth — using an app-specific password.
- Windows code signing — unchanged.
- Auto-update — `publishAutoUpdate: false` stays as-is.
